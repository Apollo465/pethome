## 意见 1｜缺少 AI 文本生成资质证明文件

**结论：本版本应用内已无 AI 文本生成模块，不需要《安全评估报告》。**

依据与事实：

1. 本版本删除了「我的 → 云端 AI」整块功能（原功能是用户自行填写第三方模型地址与 Key 后由应用转发生成请求），
   应用内已不存在任何调用生成式模型的代码路径；
2. 包体内不含模型文件、不含任何服务端密钥或第三方服务密钥；
3. 已从 `module.json5` 中删除 `ohos.permission.INTERNET`，应用不具备联网能力，不存在向外部服务提交文本的通道；
4. 原「AI 养宠问答」已改名为「养宠问答」，其答案来自应用内置的本地知识库：
   约 70 条食物安全条目 + 27 个养宠科普话题，按关键词匹配后直接展示预置文案，未命中时回答"知识库里没有"；
5. 依据审核意见 1 的修改建议（2）"若应用内已无相关模块，可在 AGC 备注区域进行备注说明"，本条按备注说明处理。

复现路径：应用内任意页面 → 底部「问答」→ 输入"狗能吃葡萄吗"或点选推荐话题，可见回答与出处标识。

## 意见 6｜问答未做真实身份信息认证

**结论：已按要求把应用改为「先登录后才能使用」，并在登录环节完成用户真实身份信息核验。**

实现方式（可截图验证）：

1. 启动应用首先进入**登录门禁页**，未登录无法进入首页、食物、问答、我的任何页面；
2. 登录方式为**华为账号**（系统 Account Kit）：华为账号是实名账号，注册与使用均已由华为完成实名认证，
   **登录即完成用户真实身份信息核验**，我们不再额外索取姓名、身份证件号码或人脸信息；
3. 登录后只在**本机**保存账号标识（openID/unionID）与登录时间，不建设用户数据库、不上传；
4. 提供「我的 → 退出登录」与「我的 → 注销账号」（后者删除本机全部数据并退出登录）；
5. 隐私政策已新增「账号与真实身份信息核验」一节，如实披露上述处理方式。

复现路径：全新安装 → 启动 → 出现登录门禁页 → 使用华为账号登录 → 进入应用主体。

> 配置说明（开发者侧）：华为账号登录需要在 AGC 开通「华为账号」服务并配置签名证书指纹，
> 必要时在 `module.json5` 中补充 `client_id` 元数据；未配置时应用会明确提示错误码与配置方法。

## 意见 7｜功能异常

### 7-1 首页 / 我的 → 新建提醒：保存时提示"提醒设置失败"

**根因**：系统代理提醒接口 `reminderAgentManager.publishReminder` 在系统通知未开启时会直接抛出
错误码 `1700001（Notification is not enabled）`；旧版本没有区分这个情况，也没有引导用户打开通知，
只弹出一句"提醒设置失败（1700001）"，看起来像是保存失败。

**修复**：

1. 保存前先查询并申请通知授权（`notificationManager.isNotificationEnabled` / `requestEnableNotification`），
   系统弹窗里允许后即可正常注册；
2. 仍失败时按错误码给出人话解释：`1700001` 通知未开启、`1700002` 系统提醒数量达上限（30 条）、
   `201` 权限问题、`401` 参数问题，并提供"去开启通知"按钮（`notificationManager.openNotificationSettings`）；
3. 无论系统代理是否注册成功，提醒都会保存在应用内今日待办中，不会丢；
4. 提醒详情页对未注册成功的提醒显示"这条提醒还没注册到系统代理"，并提供"重试注册系统提醒"；
5. 用户从系统设置打开通知回到应用时（`onForeground`），会自动补注册所有未注册的提醒。

**复现**：新建提醒 → 保存 → 允许通知后提示"提醒已设置，到点会通知你"；
若在系统设置里关闭通知再保存，会弹出"系统通知未开启"的说明与"去开启通知"入口。

### 7-2 首页 → 同步到桌面卡片：点击无响应

**根因**：旧实现里 `refreshCard()` 在"用户还没添加过桌面卡片"时直接 `return`，没有任何提示，
所以点击看起来毫无反应。

**修复**：

1. `refreshCard()` 现在返回结果（卡片总数 / 成功数 / 失败数）；
2. 未添加卡片时，弹窗说明添加路径："长按桌面空白处 → 服务卡片（卡片）→ 找到「爪心 · 今日养宠待办」→ 拖到桌面"；
3. 已添加时提示"已同步到 N 张桌面卡片"，部分失败时提示成功与失败数量；
4. 首页按钮文案随状态变化：没有卡片时显示"如何添加桌面卡片"，并在卡片下方给出文字说明；
5. 卡片已被删除时（错误码 `16501001`/`16501003`）自动清理失效记录，避免后续一直失败。

### 7-3 我的 → 宠物档案：修改信息后需要重启应用才更新

**根因**：列表使用 `ForEach` 渲染并以数据 `id` 作为键（keyGenerator），档案内容变化而 id 不变时，
ArkUI 认为该项没有变化，不会重新渲染列表项，因此要等重启后重建页面才看到新数据。

**修复**：宠物列表与提醒列表的 key 改为"id + 内容字段"（名字 / 品种 / 生日 / 体重 / 照片 / 提醒时间 / 重复规则等），
内容变化即视为新项，返回列表立即刷新。今日待办列表同样处理。

**复现**：我的 → 宠物档案 → 编辑 → 改名字/体重 → 保存返回，列表立即显示新内容。
