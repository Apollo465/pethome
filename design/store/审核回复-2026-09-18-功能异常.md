# 爪心 v1.0.1 对 2026-09-18 审核意见（功能异常）的修改说明

包名 `com.pethome.xiaohong`｜版本 1.0.0 → 1.0.1（versionCode 1000000 → 1000001）
测试环境：HarmonyOS 6.1 / API 24 / 简体中文

---

## 一、首页/我的-新建提醒：保存时提示"系统提醒注册失败"——已修复

### 定位到的两个问题点（都在客户端）

1. **代理提醒的参数不符合系统规格，被系统直接拒掉。**
   上一版给日历提醒设置了「延时提醒次数 `snoozeTimes = 2`」，却没有设置与之配套的
   「延时提醒间隔 `timeInterval`」。按系统规格，两个字段必须成对出现，且 `timeInterval`
   最少 30 秒。这类参数不合规会被系统按参数错误拒绝（错误码 **1700007**）。
   旧代码只把 1700001 / 1700002 / 201 / 401 翻译成了中文说明，其余错误码一律落进兜底分支，
   统一显示成"系统提醒注册失败（错误码 xxx）"，因此审核看到的正是这句兜底文案。
2. **系统通知开关为关闭状态时，代理提醒必然被系统拒绝（错误码 1700001）。**
   上一版把这件事做成了阻断式弹窗，用户即便只想把提醒记在应用内，也会被"失败"提示挡住。

> 同时保留了详细日志（hilog 标签 `ReminderService`，成功与失败都会打印错误码），
> 若复测仍有异常，可以直接按日志里的错误码定位。

### 修改内容

| 项 | 本次修改 |
| --- | --- |
| 延时提醒参数 | 补齐 `timeInterval = 300`（秒），与 `snoozeTimes` 成对出现；精简参数重试时两者一起不传 |
| 提醒时间 | 交给系统前统一换算成"将来的时间"：重复提醒落到下一个符合的星期，一次性提醒已过期时明确提示改时间，不再把过去的时间交给系统 |
| 通知渠道 | 注册前先确认代理提醒使用的通知渠道已存在（`notificationManager.addSlot`） |
| 通知授权 | 保存时先确认系统通知开关，需要时弹出系统授权；用户不同意也照常保存，不阻断 |
| 失败重试 | 先按完整参数发布，被系统拒绝时自动以最精简参数再发布一次 |
| 错误码说明 | 补全 1700007 等错误码：条数上限、权限、参数、通知未开，各给一句人话与下一步 |
| 保存与注册解耦 | **先落库、再注册**：提醒一定进入应用内「今日待办」，不会因为系统侧的问题丢失用户填写的内容 |
| 反馈方式 | 不再弹"失败"弹窗。成功提示"提醒已保存，到点会通知你"；未注册上则提示"提醒已保存到「今日待办」"，并在当前页给出「去开启通知」「重试注册系统提醒」 |
| 我的-提醒与通知 | 新增状态卡片：显示系统通知开关、提醒总数、已交给系统按时提醒的条数，并提供「检查并修复」一键补齐注册 |
| 防重复 | 保存成功后同一条提醒切换为"已存在"，再次点保存不会产生重复提醒 |

## 二、食物-拍照识别：提示"图像检测暂不可用"——已修复

### 根因与设计意图说明

拍照识别用的是系统端侧能力（CoreVisionKit 目标检测）。该能力是否可用取决于机型和系统版本：
模型资源可能缺失、引擎服务可能异常，此时 `ObjectDetector.create()` 会直接失败。
上一版把这个失败原样抛给用户（"图像检测暂不可用，请手动确认食物名称"），用户看到的是一次功能异常。

另需说明这个功能的**设计意图**：系统端侧检测只能判断画面里"有没有食物 / 猫狗"，
**无法识别具体是哪种食物**（接口给出的标签只有 Food、Cathead、Doghead 这类粗分类）。
所以本应用一直是「系统给一个提示 → 用户点选确认具体食物 → 本地知识库给出能不能吃的结论」，
具体食物种类始终由用户确认，结论来自应用内置的本地知识库（预置文案）。

### 修改内容

| 项 | 本次修改 |
| --- | --- |
| 输入预处理 | 送检前把照片按最长边缩到 1280 像素再解码（原图直送容易超内存/超时）；缩放解码失败自动退回原尺寸 |
| 检测重试 | 端侧服务偶发"服务异常"时，同一进程内重试一次 |
| 资源回收 | 检测器、PixelMap、文件句柄全部在 finally 中释放 |
| 流程不再依赖检测 | 选完照片立刻给出可操作的下一步：照片预览 + 名称输入框 + 常见食物点选；确认后直接出本地知识库结论 |
| 文案 | 不再出现"暂不可用"。检测成功时补一句观察结果（"画面里有食物"）；没跑起来时只显示"请点选或输入照片里的食物"，后续步骤完全一致 |

结论：**任何机型上「选照片 → 点选确认 → 得到能不能吃的结论」都能走通**，
端侧检测由"决定功能是否可用"改为"锦上添花的提示"。

## 三、建议的复测路径

1. **新建提醒**：首页 → 添加提醒 → 选一个将来的时间 → 保存。
   - 系统通知已开启：应看到 Toast「提醒已保存，到点会通知你」，并返回首页、出现在「今日待办」。
   - 系统通知关闭：应看到「提醒已保存到「今日待办」」的提示与「去开启通知」按钮，
     提醒依旧出现在「今日待办」；点「重试注册系统提醒」可再次注册。
   - 「我的 → 提醒与通知 → 检查并修复」应提示"已补上 N 条提醒"。
2. **拍照识别**：食物 → 拍照识别 → 选择一张照片 → 在卡片里点「巧克力」或输入食物名称 →
   应给出"不能吃 / 谨慎 / 可以吃"的结论文案与来源标识。
3. 关于版本：应用内「我的」页脚显示 v1.0.1，`AppScope/app.json5` 的 versionCode 为 1000001。

> 本版本仍然不声明 `ohos.permission.INTERNET`：提醒与照片识别都是系统端侧能力，
> 档案、照片、问答内容依旧只保存在本机。
